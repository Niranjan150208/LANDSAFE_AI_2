# LANDSAFE AI

A responsive disaster-risk monitoring prototype focused on landslide-prone corridors in North East India. It combines an explainable five-factor risk score, deterministic demo scenarios, incident reporting, and offline report queuing.

## Features

- **Risk assessment:** 24-hour rainfall, 72-hour antecedent rainfall, soil moisture, slope, and peak ground acceleration (PGA), with explicit weights and factor-level explanations.
- **Scenario simulation:** one-click `HIGH_RISK` and `SAFE` scenarios evaluated by the same API risk engine.
- **Incident reporting:** severity-validated incident submissions, server-side persistence during runtime, and duplicate protection using a client report ID.
- **Offline queue:** browser-local incident queue with automatic replay when connectivity returns.
- **Health endpoint:** `GET /api/health`.
- **CI:** Node test suite and syntax checks via GitHub Actions.

## Run locally

Requires Node.js 22 or later.

```bash
npm install
npm start
```

Open http://localhost:3000.

Run tests:

```bash
npm test
node --check server.js
node --check public/app.js
```

## API

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Service status and mode |
| GET | `/api/dashboard` | Recent risk, alerts, and incidents |
| GET | `/api/risk/model` | Factor weights and thresholds |
| POST | `/api/risk/evaluate` | Evaluate a supplied factor set |
| POST | `/api/demo/scenario` | Run `HIGH_RISK` or `SAFE` |
| GET | `/api/incidents` | List incident reports |
| POST | `/api/incidents` | Create an incident |
| POST | `/api/incidents/sync` | Sync an offline incident |
| GET | `/api/alerts` | List risk alerts |

Example scenario request:

```bash
curl -X POST http://localhost:3000/api/demo/scenario \
  -H "Content-Type: application/json" \
  -d '{"scenario":"HIGH_RISK"}'
```

## Deploy on Render

1. Open the Render dashboard and choose **New → Blueprint**.
2. Connect this repository and select the branch containing `render.yaml`.
3. Review the service settings and create the web service.
4. After deployment, check `https://YOUR-SERVICE.onrender.com/api/health`.

The included blueprint targets Render's free web-service plan and writes its JSON state under `/tmp`. **Free-instance storage is ephemeral**; stored reports may be lost on restart or redeploy. For persistent production data, attach a supported persistent disk on a paid instance or replace the JSON store with a managed database. This project does not automatically create a Render service or access your account.

## Risk model and safety

The current calibration anchors are illustrative and designed for a reproducible hackathon demonstration. They are **not a scientifically validated landslide prediction model** and must not be used as the sole basis for evacuation or other real-world emergency decisions. Labels and messages generated by the scenarios are simulated; follow official local authorities and emergency services.

## Security / production hardening

This is a demo, not yet a hardened public emergency service. Before production use, add authenticated users and role-based authorization, rate limiting, audit retention controls, managed persistent storage, monitoring, and review of model calibration by qualified geotechnical and disaster-management experts.
